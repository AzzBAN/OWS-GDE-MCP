# App Development Process

The system supports integrated orchestration. That is, in various orchestration scenarios, assets can be orchestrated through the unified entry of project management and follow the unified process covering project management, deployment and debugging, as well as packaging and release.

This section describes how developers develop assets based on the integrated orchestration capability.

![[en-us_image_0000001618890165.png]]

**Table 1** Description of the asset development process based on the integrated orchestration capability  
| Development Phase | Description |
| :-- | :-- |
| Preparations | Individual developers need to learn about the information in Preparations by Developers. Tenant-level or team-level developers also need to learn about the information in Preparations by Tenant Administrators. |
| Setting up a project | A project is the basis of integrated orchestration. All development activities start from project creation. For details, see Setting Up a Project. |
| Developing a scenario-based app | The orchestration elements to be created during app development vary according to application scenarios. Developers can determine the orchestration elements to be used based on the actual service scenario and refer to the corresponding sections:
-   [[Orchestration of Simple Object Management Apps|Orchestration of Simple Object Management Apps]]
-   [[Network Operation Automation|Network Operation Automation]]
-   [[Configuring a Process|Configuring a Process]]
-   [[RPA Orchestration|RPA Orchestration]]
-   [[API Orchestration|API Orchestration]]
-   [[GDELink Mobile App Orchestration|GDELink Mobile App Orchestration]]
-   [[Data Visualization Screen Orchestration|Data Visualization Screen Orchestration]]

 |
| Deploying and debugging the app | After developing orchestration elements in the develop-state environment, you need to deploy the app in the runtime-state environment and then debug it. For details, see Debugging During App Development. |
