# Format of a GTS Standard Asset Package

**Table 1** GTS Standard Package Format   
| Compressed File | Mandatory | Description |
| :-- | :-- | :-- |
| {Asset package name}.zip | Y | Release package. Compress the files in this directory. There is no root directory. |
| ├─meta.json | Y | Asset metadata, which stores asset release information |
| ├─release | N | \- |
| │ ├─quality.json | N | Quality & Trustworthiness Check Result |
| │ ├─release\_notes.md | N | Description of the version modification point during release. The value is encoded in UTF-8 format and is relative to the image in the pictures/ directory. |
| │ ├─pictures | N | \- |
| │ │ ├─xxx.jpg | N | \- |
| ├─resources | Y | Directory for storing resource files uploaded by users for asset display on the GDE Store. |
| │ ├─logo.png | N | Asset logo displayed on the GDE Store. The pixel must range from 64 x 64 to 90 x 90. |
| │ ├─background.jpeg | N | Background image, displayed as the background of the asset logo, 64–96 px, <500 KB |
| │ ├─homepage.jpeg | N | Large image on the home page, which is used for asset recommendation display. When the operation personnel recommend the asset to users, the file is zoomed in. The size of the file ranges from 64 px to 96 px and the size of the file is less than 500 KB. |
| │ ├─introduction | Y | \- |
| │ │ ├─summary\_zh\_cn.txt | Y | Chinese description of the asset, which is encoded in UTF-8 format and contains a maximum of 30 Chinese characters. |
| │ │ ├─summary\_en\_us.txt | Y | English description of the asset, which is encoded in UTF-8 format and contains a maximum of 60 English characters. |
| │ │ ├─detail\_zh\_cn.md | Y | Asset details in Chinese, such as the application scenario, tutorial, and example of the asset. The value is in UTF-8 encoding format. |
| │ │ ├─detail\_en\_us.md | Y | Asset details in English, such as the application scenario, tutorial, and example of the asset. The value is in UTF-8 encoding format. |
| │ │ ├─pictures | N | \- |
| │ │ │ ├─xxx.png | N | detail\_en\_us.md or detail\_zh\_cn.md relatively references images in this directory. |
| │ │ ├─docs | N | \- |
| │ │ │ │ ├ ─ {Document name}.{Suffix} | N | detail\_en\_us.md or detail\_zh\_cn.md references documents in this directory, such as help documents and third-party open-source software usage instructions. The suffix includes .doc|.docx|.xls|.xlsx|.ppt|.pptx|.zip. |
| ├─security | N | \- |
| │ ├─security.zip | N | Trustworthiness self-check package, such as ICSL test report |
| ├─packages | Y | \- |
| │ ├ ─ {Asset software package name}.{Suffix} | Y | Asset software package. The file name extensions include: .zip|.tar|.gz|.gpk|.gdk|.itf|.bpm|.jar|.7z |
| {Asset package name}.zip.p7s | Y | Digital signature of the asset package, which is used for asset source tracing | **Table 2** meta.json format    
| Field | Type | Mandatory | Description |
| :-- | :-- | :-- | :-- |
| id | Character string | Y | Asset ID, which uniquely identifies an asset. It is generated by the asset provider. UUIDis a number of 16 bytes and 128bits and is usually represented by a character string of 36bytes, for example, 3F2504E0-4F89-11D3-9A0C-0305E82C3301;. |
| name | Character string | Y | Asset name, which contains 64 characters, including letters, digits, underscores (\_), and hyphens (-). |
| version | Character string | Y | Release version, in dotted notation. The content is "V version.R version.C version". For example, 1.4.1 indicates V100R004C01. |
| category | Enumeration | Y | Asset category, including App and BuildingBlock and their subcategories. For details about the enumerated values, see the attachment category.xlsx. |
| domain | Enumeration | Y | Business domain, which describes the GTS business domain to which the asset is applicable. A business domain has sub-business domains. A maximum of six levels of sub-business domains are supported. For details about the enumerated values, see the attachment domain.xlsx. |
| releaseRegion | \[Enumeration\] | Y | The release area to which the asset is intended. The asset can be used only in these restricted areas. Enumerated value of the list. The options are as follows:
-   ALL: indicates that the license can be used globally.
-   If the document is released for the combination of regions and carriers outside China, use the following code: OC-OP\_nnnnn, where **OC** indicates the combination of regions and carriers outside China, **OP\_nnnnn** indicates the combination of regions and carriers outside China. For details, see the attachment. If this parameter is set to OC-ALL, the tool can be used in all regions outside China. If ~ is added before OP\_nnnnn, for example, ~OP\_nnnnn,, the tool can be used in all regions except this region.
-   If the release is a combination of regions and carriers in the China Region, use the following code: CN-Region level-2 code-Region level-3 code-Carrier code. The regional level-2 code and regional level-3 code can be omitted. If the regional level-2 code is omitted, it indicates that the carrier code can be used in the entire China Region. The format of the carrier code is OP\_nnnnn, where nnnnn is a number. For details, see the attachment. If ~ is added before an area, for example, ~, the area can be used in all areas except this area. ~ cannot be added before OP\_nnnnn.

For details, see the attachment releaseRegion.xlsx. |
| eomTime | Numerical value | Y | End of marketing (EOM) time of an asset. The format is MM/DD/YYYY. The time is GMT+00. |
| eosTime | Numerical value | Y | End of service (EOS) time of an asset. The format is MM/DD/YYYY. The time is GMT+00. |
| developerType | Enumeration | Y | Indicates whether an asset is developed by an individual developer or a team developer. The options are as follows: 1: individual developer 2: team developer |
| devTeam | Character string | Y | Development team of the asset. The team name contains 64 characters. devTeam.xlsx |
| techSupport | \[Character string\] | Y | Technical support contact information, which contains at least the following items: service content, service duration, hotline, and email. A maximum of five items are allowed. The number of characters in each item cannot exceed 300. For example: Service duration: 9:00–18:00 Service content: hotline support, remote services, on-site maintenance, and training services Service hotline: 123456789 Service email: xx@xx.com |
| otherTags | \[Character string\] | N | List of asset tags added by developers. Use commas (,) to separate multiple tags. Each tag can contain a maximum of 64 characters. A maximum of 16 tags are supported. |
| ootb | Boolean | Y | Out of the Box (OOTB): indicates whether an asset can be used out of the box. The options are True and False. If the value is True, the asset does not require secondary development and customization. If the value is False, the asset can be used only after secondary development and customization. |
| platform | Character string | Y | For details, see the Use Platform field in Asset Package Tag. |
| platformVersion | Character string | Y | Platform version. The format is V version.R version.C version. For example, 1.4.1 indicates V100R004C01. |
| isManaged | Boolean | Y | Indicates whether the modification of an asset is controlled. The value can be True or False. True indicates that the asset is controlled, that is, the asset user (including other developers) cannot modify the asset (even if the internal implementation of the asset is visible). False indicates that the asset is not controlled, that is, the asset user can modify the implementation of the asset, enhance or delete the asset, and then release the asset again. |
| deploymentMode | Enumeration | Y | Deployment mode. The value can be SaaS or OP. SaaS indicates that the service is deployed as SaaS. OP indicates that the file needs to be downloaded before being used. |
| maturity | Character string | Y | Maturity. L1: assets are not mature and are in the exploration/maturity phase. They are for internal use only. L5: assets are mature and can be used externally. \* Other levels can be added as required. |
| openness | Enumeration | Y | Mode in which an asset provides capabilities. The options are as follows: ServiceAPI: describes APIs of existing services (including SaaS and local services) through asset packages. LibAPI: APIs invoked locally. The asset package contains two parts: service capability implementation and service capability API description. NonAPI: Capabilities are provided in non-API mode. For example, a specific section is used to describe input parameters in a template, for example, the inputs section in the TOSCA template. |
| dependencies | \[{}\] | N | Definition of dependency on other GTS standard asset packages. Enter the list of dependent assets {name, version}. | The GTS standard asset package consists of two types of software packages: app and BuildingBlock. The standard packaging format of apps is as follows:

  
| Directory structure | Mandatory | Description |
| :-- | :-- | :-- |
| {App asset package name}.gpk | Y | The format is gpk, which is essentially zip. Scenario assets that support this format can be installed through GDE AppManager. |
| ├─manifest.json | Y | (Mandatory) Asset metadata file, which is used to briefly describe assets |
| ├─category.json | Y | Category |
| ├─resources | N | (Optional) Asset resource file, such as the registration certificate, birth certificate, icon, and help document |
| │├─birth\_permit.json | N | Specific module and content of the registration certificate |
| │├─birth\_certificate.json | N | Specific module and content of the birth certificate |
| ├─modules | Y | Asset module folder, which is used for internal asset layering |
| │├─module\_name | Y | Specific modules are customized by developers as long as they do not conflict with each other in the asset package. |
| ││├─module.json | Y | Metadata Description of a Module |
| ││├─studio.json | N | Description of the corresponding designer. |
| ││ ├ ─ {Orchestration domain} | Y | Orchestration domain, such as common jobs, automatic network orchestration, and data orchestration |
| │││├─package.json | Y | Packaging information, including the engine type, engine name corresponding to each package, package file name, and manifest version |
| │││├─brief.json | Y | Element name and URI |
| │││ │ ─ {Orchestration engine}{.}{zip|tar} | Y | The file or folder of the corresponding engine can be compressed or not. If the file or folder is not compressed, it is automatically compressed into a .zip package. |
| ││ ├ ─ {Asset scenario ID} | N | Assets in Multiple Scenarios |
| ├─libs | N | Referenced Component Library |
| │ ├ ─ {Component type} | N | Component type folder. A maximum of two levels are supported. |
| ││ ├ ─ {Component asset category ID}.{gdk|zip} | N | Multiple component assets can be included. | For details, see [AssetsPackageFormatV1.3.xlsx](../resource/AssetsPackageFormatV1.3.xlsx).

The format of the BuildingBlock package is not limited. If the BuildingBlock package needs to be added to the integrated orchestration, the middle end needs to parse the package as follows:

  
| Directory structure | Mandatory/Optional | Description |
| :-- | :-- | :-- |
| {BuildingBlock asset package name}.gdk | Y | The format is gdk, which is essentially zip. Scenario assets in this format can be imported through tenant assets. |
| ├─manifest.json | Y | Asset metadata file, which briefly describes assets. For details about the format, see the app asset package. |
| ├─resources | N | (Optional) Asset resource file, such as the registration certificate, birth certificate, icon, and help document |
| │├─birth\_permit.json | N | Specific module and content of the registration certificate |
| │├─birth\_certificate.json | N | Specific module and content of the birth certificate |
| ├─components | Y | DSL file folder for storing specific building block assets |
| │ ├Indicates the metadata of the ─ asset. | Y | DSL file for storing specific building block assets | **Parent topic:** [[Asset Package Specifications|Asset Package Specifications]]
