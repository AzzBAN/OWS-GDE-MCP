#### Procedure

1.  Click the name of the endpoint to be configured, and choose **Endpoint-Level Policy** > **Authentication Method**.
2.  Set the authentication mode.
    
    When a request is forwarded to a southbound service, the southbound service needs to authenticate the request before forwarding it to a third party. The authentication policy is used for configuring southbound service call. The supported authentication modes are as follows:
    
    -   **No Authentication**
        
        No authentication is performed on southbound services.
        
    -   **Basic Authentication**
        
        You need to enter the password obtained from the endpoint on the API Manager. The username is user-defined.
        
    -   **GDE Store**
        
        The app key needs to be selected based on the request header. Choose **Endpoint Management** > **HTTP Service Management/SOAP Service Management** in the API Governance, and set the secret key.
        
    -   **GAM Authentication**
    -   **Username and Password**
        
        For details about how to configure extended authentication of the username and password, see [[Authentication|Configuring Attribute Variables of Extension Policies]].
        
    -   OAuth 2.0
        
        **Table 1** Parameters  
        | Parameter | Description |
        | :-- | :-- |
        | Authentication Service Address | Service address provided by Huawei IT Service (HIS) for the client to apply for tokens. |
        | Client ID | Client ID, for example, AK of the client. |
        | OAuth type | NOTICE: During the extension, do not change the names of the predefined functions. When the endpoint is called, the API Access module of the API Fabric sends a request message containing the token field to the endpoint based on the extended JavaScript script.
        -   **Custom scripts** If Custom scripts is selected, set Authentication Service Address to the address of the server that performs token authentication, and Client ID to the app ID in the JavaScript script. On the API Governance page, the two parameters are read synchronously and you need to enter the client key obtained from the endpoint.

         | -   WSSE
        
        This feature applies only to Huawei Cloud scenarios.
        
        You can configure **APPKey** and **SecretKey** on the API Portal to implement WSSE authentication. When an external system calls an API, the API Fabric forwards the request to the southbound system for processing and adds **Authorization** and **X-WSSE** to the request header. The following table describes the configuration.
        
            
        | Parameter | Mandatory | Parameter Type | Default Value | Description |
        | :-- | :-- | :-- | :-- | :-- |
        | Authorization | Yes | String | \- | Set this parameter to WSSE realm="{SDP}",profile="{UsernameToken}",type="{Value of APPKey}". |
        | X-WSSE | Yes | String | \- | Set this parameter to UsernameToken Username="{Value of APPKey}", PasswordDigest="{Value of PasswordDigest}", Nonce="{Random number}, Created="{Time when the random number is generated}". PasswordDigest: The value is generated based on PasswordDigest = Base64 (SHA256 (Nonce + Created + Password)). The value is a character string generated by combining Nonce, Created, and Password, and is encrypted using SHA256. The character string does not contain the plus sign (+) or spaces. Password is the value of SecretKey. Nonce: A random number generated when a customer sends a request. The value is a string of 1 to 128 characters, including digits, and letters. For example, 66C92B11FF8A425FB8D4CCFE0ED9ED1F. Created: Time when a random number is generated. The value is in the standard UTC format, for example, 2018-02-12T15:30:20Z. | 3.  Click **Save**.
