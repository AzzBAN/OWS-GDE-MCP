#### Processing Rules

The rules for JS script processing are as follows for the arrays in the same dimension but in different mapping scenarios:

1.  Assign a value on only the root element. The tool assigns a value on the array object.
2.  Assign a value on only the sub-element. The tool generates the following FOR loop statement:
    
    for(int i = 0; i<X.length; i++){
    Z.\[i\].e = X\[i\].a;
    Z.\[i\].f = X\[i\].b;
    }
    
3.  Assign values on the root element and sub-element, as shown in [Figure 1](#EN-US_TOPIC_0000001538418337__en-us_topic_0129536986_fig111618101643). The tool assigns values on the array objects.
    
    **Figure 1** Assigning values on the root element and sub-element  
    ![[en-us_image_0240743959.png]]
    

The value in the **Js Editor** window has a higher priority than that in **Array Mapping code generated by system**. That is, if a user assigns a value on an array, as shown in [Figure 2](#EN-US_TOPIC_0000001538418337__en-us_topic_0129536986_fig13845163619536), the tool uses the value as the actual mapping value. The JS in **Array Mapping code generated by system** does not take effect.

![[note_3.0-en-us.png]]

The code in **Array Mapping code generated by system** is automatically generated by the tool for reference but cannot be modified.
